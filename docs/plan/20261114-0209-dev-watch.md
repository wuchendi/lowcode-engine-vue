# 20261114-0209-dev-watch Rebuild workspace packages during designer development

- **createdAt**: 2026-11-14 02:09

## Context

- `pnpm dev` runs `pnpm -C apps/designer dev` =
  `nsl run -n lowcode-vue -c -- vite --port NSL_PORT --strictPort`
  (http://lowcode-vue.localhost:3355). nsl only maps the port; nothing
  rebuilds the packages.
- The designer uses build outputs only:
  - `serveRuntime` (apps/designer/vite.config.mts) serves
    `renderer/vue{2,3}/dist/{renderer.umd.js,simulator.umd.js,simulator.css}`,
    `plugins/engine-ext-vue/dist/engine-ext.{js,css}` and
    `materials/*/dist` (the designer's assets JSON loads
    `index.js`, `index.css`, `meta.js`). Files are read per request.
  - The designer page imports `@cdlab996/lowcode-vue3/designer` and the
    plugins `directive-loading`, `manual`, `set-doc-url`,
    `vue-code-editor` from their `dist`.
- Packages:
  - renderer vue2/vue3: one tsdown config = ESM (+ dts, + copy of
    `core/src/simulator/simulator.css`) and two minified UMD bundles;
    `clean: !options.watch` is already there. `designer.ts` only re-exports
    `@cdlab996/lowcode-vue-core/designer`, whose package exports point at
    source.
  - plugins directive-loading / manual / set-doc-url: tsdown, plain TSX
    (React classic, no styles needed by the designer config).
  - vue-code-editor: Vite lib build with UnoCSS and its own plugins; its
    source cannot be compiled by the designer config without copying those.
  - engine-ext-vue: Vite IIFE build (+ tsc declarations).
  - materials: `start` = `lowcode-material dev`, which watches index/meta
    but also starts a preview server on port 9000 (fixed default) and
    rewrites `dist/assets.json` with local URLs.
- A full watch would be 14 build processes (2 renderer, 5 plugins, 6
  materials, builder), with dts and minification on every save.

## Proposal

Revised (option B, chosen 2026-11-14): the designer's Vite dev server does
not work with the CDN globals (see Annotations), so development uses the
designer build, which is the verified path.

1. Renderer vue2/vue3: `dev` script `tsdown --watch`; in watch mode the
   config returns only the two UMD bundles, unminified, no ESM/dts. (done)
2. `dev` scripts for on-request watching: engine-ext-vue and
   vue-code-editor `vite build --watch`; materials run
   `lowcode-material dev` with a distinct `--port` each. (done)
3. Designer (`apps/designer`), development mode (`--mode development`):
   - `vite build --watch --mode development`: unminified designer build;
     the plugins and `@cdlab996/lowcode-vue3/designer` are bundled from
     their builds as in production (their watchers or a `pnpm build` update
     them).
   - `dev` script = `nsl run ... vite preview --mode development`;
     `dev:bare` the same on port 5577. In development mode the preview
     server serves the runtime files (renderer bundles, engine-ext,
     materials) straight from the packages, `simulator.css` from the core
     source, and reloads the pages through a small server-sent-events
     endpoint when the designer output or a served package output changes
     (client snippet added to the HTML only in development mode).
   - The source aliases and the dev-server reload added earlier are
     removed; the existing dev-server middleware is left as it was.
4. Root `scripts/dev.mjs` (`pnpm dev`): designer build watch, designer
   preview (nsl), the two renderer watchers, plus `--watch <names>`
   (material directory names, `engine-ext-vue`, `vue-code-editor`); output
   prefixed per task; all children stop on exit or when one fails.
5. README (Getting started, Scripts) and changelog.

Verification (tooling, manual): `pnpm dev --watch vant4,engine-ext-vue` in
tmux; edit core TS, `simulator.css`, a designer source file, the manual
plugin (with its build), engine-ext and vant4; Playwright checks each change
reaches the page without manual steps; Ctrl-C leaves no processes; lint,
lint:type, tests, `pnpm build:designer` output unchanged in production mode.

## Risks

- Designer source changes take a rebuild (~2 s) and a full reload; no HMR.
- Plugins other than the opt-in ones need `pnpm build` of that plugin (or
  its own `tsdown --watch`) to reach the designer.
- Renderer watch mode outputs unminified UMD files into `dist`; `pnpm
  build` restores the release output (tsdown cleans outside watch mode).
- Material dev rewrites `dist/assets.json` with local URLs (existing
  behaviour); the designer does not read it, and `prepack` rebuilds.

## Scope

New `scripts/dev.mjs`; root `package.json`; `apps/designer/vite.config.mts`
and `package.json`; renderer vue2/vue3 `tsdown.config.ts` and
`package.json`; engine-ext-vue and vue-code-editor `package.json`; README;
changelog.

## Alternatives

- Watch every package (14 processes): rejected, see Context.
- Add a `--watch` (no server) mode to the material builder instead of
  running `lowcode-material dev` per material: cleaner for materials, but a
  builder change; can follow if opt-in material watching is used often.
- Compile vue-code-editor from source too: needs its UnoCSS/React plugins
  in the designer config; rejected.

## Annotations

- Blocked during verification: the designer's Vite dev server does not work,
  independently of this change (same result with the committed
  vite.config.mts): no canvas, 500s on pre-bundled chunks.
  - `optimizeDeps.exclude: Object.keys(GLOBALS)` also excludes subpaths, so
    pre-bundled chunks keep bare imports (`@alifd/next/es/*`,
    `lodash/isEqual`, `prop-types/*`, `react/jsx-runtime`) that the designer
    cannot resolve.
  - Without `exclude`, app code imports the `module.exports = window.X`
    virtual modules directly and named imports fail (no CJS interop outside
    pre-bundling).
  - Routing those ids through pre-bundling (`include`) resolves the real
    packages first: engine-ext gets its IIFE file (no exports) and the engine
    would be bundled instead of using the page global.
    Done so far (uncommitted): renderer watch config and `dev` scripts,
    engine-ext / vue-code-editor `dev` scripts, `scripts/dev.mjs`, designer
    dev aliases / source css / reload. Verified: watchers start and rebuild;
    `pnpm dev --watch` parsing. Option B chosen; revised plan approved 2026-11-14 02:21.
- Implementation notes (option B): the designer build writes
  `dist/.build-stamp` after its files and the preview reloads on it (a
  whole-`dist` watch reloaded mid-build, when the output was emptied, and the
  broken page then missed the final reload); removals of the stamp are
  ignored. Sass deprecation warnings of Fusion (the only Sass in the
  designer) are silenced and tsdown's bundling hint is turned off for the
  renderer UMD bundles: they flooded the `pnpm dev` output. Verified with
  `pnpm dev --watch vant4,engine-ext-vue`: core TS, `simulator.css`, designer
  source, engine-ext and vant4 edits each reached the page with one reload
  in ~2 s; the designer E2E passes in dev mode for both Vue versions; Ctrl-C
  stops every child; the production designer build is unchanged (minified,
  runtime files copied, no reload client).

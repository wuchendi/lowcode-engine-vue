## Context

- `generateProject(schema, { vue, packages, name, format })` runs in Node
  already; `toZip(files)` gives a zip.
- The material manifests are resolved by `materialPackages()` in
  `packages/plugins/code-generator/src/materials.ts` (the `codegen` field of
  the asset packages, otherwise the `assets.json` next to the package
  script).

## Proposal

1. Move `materialPackages()` into `@cdlab996/lowcode-code-generator` (the
   plugin imports it from there).
2. `lowcode-codegen` bin (`src/cli.ts`, Node platform build):

   ```bash
   lowcode-codegen <schema.json> --vue 3 --assets <assets.json|url> \
     [--base <url>] [--name app] [--out <dir> | --zip <file>] [--no-format]
   ```

   Reads the project schema (or a single root schema), resolves the
   manifests from the assets (`--base` for relative package URLs, default
   the assets location), writes the files to `--out` (default `./<name>`,
   refuses a non-empty directory) or a zip, prints the warnings.
3. README of the package.

Verification: unit tests for argument parsing and file output (temp dir);
run the CLI on the designer assets (served by the dev server) and on the
fixture, then `pnpm install` + `vite build` the output.

## Risks

- Relative package URLs need a base: defaulted to the assets URL, else an
  error naming `--base`.

## Scope

`packages/tools/code-generator` (cli, materials, build config, README),
`packages/plugins/code-generator` (import).

## Alternatives

- A separate CLI package: one more package for one file; rejected.

## Annotations

- 2026-11-14: a root schema has no `componentsMap`, so the generator now
  falls back to the manifest that exports a component of that name.

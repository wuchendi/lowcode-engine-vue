## Context

- `@alilc/lowcode-plugin-block` 1.0.0-beta.0 only lists blocks from a
  backend API (`config.apiList.block.listBlocks`); saving a block lives in
  the official demo, not in the plugin; the code is a debug-logging beta.
- Engine APIs: `material.addBuiltinComponentAction` (node toolbar actions),
  `canvas.dragon.from(shell, boost)` (drag node data into the canvas, as the
  components pane does), `node.exportSchema()`, `document.insertNode`.
- The designer stores schemas in `localStorage` per Vue version.

## Proposal

1. `apps/designer/src/plugins/blocks.tsx` + `src/utils/blocks.ts`:
   - node action 保存为区块 (not on the page root): asks for a name and
     stores `{ id, name, schema, createdAt }` (the node tree without ids) in
     `localStorage` per Vue version;
   - 区块 left panel: lists blocks; drag one into the canvas, or click to
     append it to the selected node's container (or the page); delete with
     confirmation.
2. Inserted blocks are copies (later edits of the block do not change them),
   like the official snippets.

Verification: unit tests for the store and the id stripping; E2E on both
versions: save a node as a block, insert it by click and by drag on another
page, save and reload, delete.

## Risks

- Blocks reference components by name: a Vue 2 block is not usable in Vue 3;
  the store is per Vue version for that reason.

## Scope

`apps/designer` (plugin, store, registration), docs.

## Alternatives

- The official block plugin with a local `listBlocks`: still needs the save
  side, screenshots and its beta code; rejected.
